La API de Claude retira el header beta que exigían los diagnósticos de caché

Cache diagnostics sale de beta en la Claude Developer Platform: ya no hace falta enviar el header cache-diagnosis-2026-04-07 para consultar el estado del prompt caching.

Anthropic movió a disponibilidad general la función de diagnóstico de caché de su API, que hasta ahora requería activarse con el header cache-diagnosis-2026-04-07. La función permite a quienes usan prompt caching ver con más detalle por qué una petición no reutilizó una entrada de caché existente, algo útil para depurar costos y latencia en aplicaciones que dependen de ese mecanismo para abaratar llamadas repetidas.

El cambio es menor en superficie, pero simplifica la integración: los equipos que ya usaban la función en beta pueden quitar el header de sus peticiones sin perder la funcionalidad, y quienes no la habían probado ya no necesitan pedir acceso especial para hacerlo.

La actualización llega en la misma ventana en la que la Claude Developer Platform sigue empujando Claude Opus 5.5 como su modelo por defecto para trabajo agéntico de larga duración, con ventana de contexto de 1M de tokens y soporte beta para herramientas insertadas a mitad de conversación en mensajes de sistema.
