GitHub lleva HydraFusion a producción en Copilot CLI y conecta Jira a Copilot

GitHub sacó de vista previa su orquestador de varios modelos por tarea y sumó una integración con Jira que lleva los tickets directo al flujo de trabajo de Copilot.

GitHub llevó a todos los planes de Copilot, dentro de /experimental en Copilot CLI, el Project HydraFusion que había mostrado en vista previa a inicios de mes. En vez de mandar cada prompt a un solo modelo, HydraFusion arma un plan de ejecución distinto por cada tarea: puede usar un modelo para el borrador, otro para criticarlo, o escalar a un modelo más fuerte cuando una revisión de calidad rechaza el primer intento. GitHub reporta que, en TerminalBench 2.1, este enrutamiento mejoró la calidad de las tareas verificadas en 4.9 puntos porcentuales con un costo estimado 67% menor frente a usar Claude Opus 5 de forma directa en cada solicitud.

En paralelo, Copilot sumó integración con Jira: los tickets llegan a un tablero compartido, el equipo elige cuáles avanzan, y Copilot lleva ese contexto hasta la investigación del problema, la implementación y la preparación del pull request.

Por qué importa

Confirma una tendencia -enrutar entre varios modelos según la tarea en vez de apostar siempre por el mismo- que otras plataformas de coding agents también empiezan a explorar, y baja el costo de usar calidad "frontier" en tareas cotidianas sin que el desarrollador tenga que elegir manualmente el modelo cada vez.
