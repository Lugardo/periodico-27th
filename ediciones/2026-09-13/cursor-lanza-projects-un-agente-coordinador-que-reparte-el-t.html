Agentic coding

Cursor lanza Projects: un agente coordinador que reparte el trabajo entre miles de subagentes

El editor de código presentó en beta un espacio de trabajo pensado para iniciativas que duran meses, donde un agente coordinador delega el código a otros agentes en vez de escribirlo él mismo.

Cursor lanzó en beta "Projects", un espacio de trabajo pensado para iniciativas de código que se extienden por meses -una migración grande, una función completa, una app entera- en vez de tareas puntuales de una sesión. Un agente "coordinador" no escribe código directamente: planea el trabajo, lo reparte entre potencialmente miles de subagentes que sí lo implementan, y regresa el resultado terminado para que una persona lo revise. Como el coordinador delega en vez de ejecutar, nunca queda bloqueado esperando y sigue disponible para recibir indicaciones nuevas.

Los Projects corren en máquinas dedicadas en la nube, mantienen archivos e investigación sincronizados entre sesiones locales y remotas, y pueden reaccionar a señales externas -un canal de Slack, un cronograma, los pull requests abiertos de un repositorio- sin que alguien tenga que arrancarlos manualmente cada vez. Cursor identifica tres patrones de uso típicos: desarrollo de features, migraciones incrementales, y trabajo de "jardinería" como mantenimiento de calidad de código y vigilancia de regresiones.

Por qué importa

Es la apuesta más clara hasta ahora de un editor mainstream por tratar el código no como tareas aisladas sino como trabajo continuo delegado a un enjambre de agentes, acercando a Cursor a lo que ya venían probando plataformas como la Agents API de OpenAI o las sesiones remotas de Claude Code.
