Agentic coding

Claude Code suma soporte para GitLab merge requests y acelera sus self-hosted runners

La actualización 2.1.233 añade URLs de merge requests de GitLab a la vista de agentes, arregla una fuga de credenciales NTLM en Windows y limita el uso de memoria de comandos Bash en Linux.

La versión 2.1.233 de Claude Code agregó soporte para URLs de merge requests de GitLab tanto en la flag --worktree como en la vista claude agents, donde ahora se muestran como !N, replicando el formato #N que ya existía para pull requests de GitHub. También se aceleró el arranque de sesiones en self-hosted runners: la rama de sesión ahora se crea sin reescribir el árbol de trabajo, eliminando dos idas y vueltas al servidor que antes bloqueaban el lanzamiento del agente.

En el apartado de seguridad, se corrigió una ruta en Windows con el prefijo de dispositivo NT (\\??\\) que lograba saltarse la validación de rutas UNC, cerrando un vector de fuga de credenciales NTLM. También se arregló un problema en conexiones MCP v2 que reabrían indefinidamente sus streams de escucha contra servidores que cortan conexiones largas por timeout, un patrón común en hosts serverless.

Entre las novedades para quienes corren cargas pesadas: ahora hay soporte opcional de cgroups de memoria para comandos de la herramienta Bash en Linux (vía CLAUDE_CODE_TOOL_MEMORY_LIMIT), pensado para que un build descontrolado no cuelgue toda la sesión. Un cambio a tener en cuenta: las herramientas de seguimiento de tareas (TaskCreate/Get/Update/List, TodoWrite) dejaron de estar disponibles por defecto en modelos más nuevos como Opus 4.8+ y Sonnet 5+; se pueden reactivar con la variable CLAUDE_CODE_ENABLE_TODO_TOOLS=1.
