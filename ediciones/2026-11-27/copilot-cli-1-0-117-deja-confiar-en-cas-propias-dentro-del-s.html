Copilot CLI 1.0.117 deja confiar en CAs propias dentro del sandbox y endurece las aprobaciones de MCP

Las versiones 1.0.116 y 1.0.117 suman variables de entorno globales, exposición explícita de herramientas para agentes personalizados y arreglan commits en worktrees enlazados.

GitHub publicó la versión 1.0.117 de Copilot CLI el 27 de noviembre. El cambio más útil para entornos corporativos es una opción de política del sandbox para confiar en certificados de CA adicionales, pensada para comandos que corren detrás de proxies que interceptan TLS. También permite que los agentes personalizados declaren explícitamente qué herramientas exponen, y corrige un problema de permisos: aprobar un servidor MCP ya no aprueba de paso las peticiones internas de Copilot cuando el nombre del servidor coincide con un tipo de permiso integrado.

En la misma versión, Autopilot ahora pide confirmación para lanzar cada extensión en lugar de bloquearlas todas, y vuelven a funcionar commits, creación de ramas y stash dentro de worktrees enlazados en los que el sandbox tiene permiso de escritura.

La 1.0.116, del 25 de noviembre, agregó un JSON Schema para validar manifiestos de extensiones en build, un ajuste env para fijar variables de entorno en todos los procesos que lanza Copilot, un aviso cuando un plugin y un servidor MCP independiente apuntan al mismo endpoint, y menor crecimiento de memoria en sesiones largas.
