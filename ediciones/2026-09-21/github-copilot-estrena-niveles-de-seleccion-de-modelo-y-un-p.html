GitHub Copilot estrena niveles de selección de modelo y un panel para depurar errores de producción con Sentry

La actualización semanal de Copilot deja elegir entre priorizar costo, equilibrio o calidad al seleccionar modelo automáticamente, y suma una integración con Sentry que lleva de un reporte de fallo a un pull request con la corrección.

GitHub publicó su tanda semanal de novedades para Copilot con dos cambios centrales para quien lo usa a diario. El primero es una nueva configuración de la selección automática de modelo con tres niveles: 'eficiencia', pensado para tareas simples y rápidas donde el costo importa más; 'balance', el punto medio recomendado para el trabajo del día a día; e 'inteligencia', que prioriza la calidad de la respuesta para tareas complejas aunque cueste más o tarde más. Los tres niveles siguen escogiendo entre el mismo conjunto de modelos disponibles, solo cambia el criterio de selección, y la opción ya está disponible en VS Code, en Copilot CLI y en la app de Copilot.

El segundo cambio es una integración nueva con Sentry dentro de la app de Copilot: un panel dedicado permite revisar errores y stack traces de producción y pedirle a Copilot que investigue la causa, valide una corrección y prepare directamente un pull request con el fix, acortando el camino entre el reporte de un fallo y su solución.

La misma actualización incluye mejoras al code review de Copilot, que ahora puede marcar como resueltos los comentarios ya atendidos en revisiones posteriores, nuevas métricas de uso dentro de VS Code y opciones para que las organizaciones gestionen solicitudes de presupuesto de uso.
