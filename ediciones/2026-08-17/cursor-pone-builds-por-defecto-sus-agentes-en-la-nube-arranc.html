Agentic coding

Cursor pone "Builds" por defecto: sus agentes en la nube arrancan hasta 3 veces más rápido

Desde hoy, todos los entornos de Cloud Agents de Cursor usan por defecto instantáneas del sistema de archivos en lugar de reconstruirse desde cero en cada sesión.

Cursor activó hoy, 17 de agosto, el uso por defecto de "Builds" en todos los entornos de Cloud Agents, tanto nuevos como existentes. La función, introducida hace unos días, prepara en segundo plano copias listas del entorno de desarrollo del usuario, para que cada agente arranque sobre una máquina ya inicializada en vez de instalar dependencias desde cero cada vez.

Según la compañía, el cambio reduce el tiempo de arranque hasta 10 veces y el tiempo hasta el primer token generado hasta 3 veces. El truco técnico es bifurcar (fork) máquinas ya inicializadas usando instantáneas del sistema de archivos, en lugar de repetir el ciclo completo de instalación. Cuando un build se completa con éxito, se convierte en la base desde la que arrancan los siguientes agentes, y Cursor mantiene copias "calientes" listas de antemano.

Para quien desarrolla con flotas de agentes en paralelo, el ahorro de tiempo muerto por sesión es directo: el comando de instalación se puede usar para todo lo que se pueda preparar con anticipación, mientras que el comando de arranque queda reservado a los servicios que necesitan estar frescos en cada sesión.
