Claude Code 2.1.325 vuelve a pedir permiso para los comandos que corren en sandbox

La nueva versión cambia un comportamiento por defecto: los comandos Bash dentro del sandbox ya no se aprueban solos. También corrige un fallo de seguridad en la descompresión zstd y añade sugerencias de prompt en VS Code.

Anthropic publicó el 13 de noviembre la versión 2.1.325 de Claude Code. El cambio que más se va a notar es que los comandos Bash que corren en sandbox vuelven a pasar por el flujo normal de permisos. Antes se aprobaban solos. Quien prefiera el comportamiento anterior puede activar `sandbox.autoAllowBashIfSandboxed: true` en su configuración.

La versión también endurece otros casos que antes pasaban sin preguntar. Las tareas programadas y `/loop` ahora piden confirmación antes de ejecutar una skill que declare `allowed-tools` o hooks. Para que corran sin supervisión, hay que agregar `Skill(nombre)` a `permissions.allow`. Además, los comandos git de solo lectura preguntan antes de ejecutarse en repositorios que no sean el del proyecto ni uno de confianza.

Entre las 88 correcciones hay un problema de seguridad en la decodificación de respuestas comprimidas con zstd y varios huecos en el sandbox y en las reglas de permisos. En VS Code llegan sugerencias de prompt (se aceptan con Tab y se apagan con `promptSuggestionEnabled: false`) y un inicio de sesión de Console que no genera una API key.

Para equipos que tienen pipelines automatizados con Claude Code, el cambio de permisos puede detener tareas que antes corrían sin intervención. Conviene revisar `settings.json` antes de actualizar.
